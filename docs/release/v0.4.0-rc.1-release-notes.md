## 1. This is a release candidate, not stable

This build is for evaluation and staged rollout with an operator who has read
the support matrix and the known limitations below. It carries the same
single-host, nested-KVM qualification boundary as v0.3.0, with the corrections
and additions listed here. It does **not** claim multi-host operation, live
(concurrent-write) migration, backup/restore as DR, Ceph/iSCSI storage,
Volvisor-backed storage, or any scale figure.

The RC must be cut from the qualified SHA and publicly verified. A build that
has not been through the lane is not qualified by association.

## 2. Scope since v0.3.0

### Audit durability

Privileged BFF mutations now leave a durable, append-only audit row
(`audit_log`), including failed and denied attempts, with redacted metadata
and bounded retention/export (#658, #688; node-facing gRPC mutations in #705).
One crash-window residual is explicitly disclosed and tracked (#706): the
audit insert happens after the handler returns, so a crash between commit and
insert can leave a mutation unrecorded. The same issue records a second
residual: mTLS-interceptor denials (missing, unparseable, or revoked
certificate) write no audit row at all.

### Migration cancellation and bounds

Migration tasks can be cancelled across control-plane restarts (#656):
`CancelMigration` flips the task token, resumes a paused source, and confirms
only after the task exits; ambiguous VMM transfers stay tracked as
"outcome unknown" rather than falsely confirming. The FinalizeAck wait is now
bounded (default 30 s) instead of hanging (#683), and the migration registry
is persisted/reconciled across restart (#691). Detached agent tasks are
cancelled after ownership ends (#707).

Pause-first stop-the-world migration (#578, Option C) is now the **only**
operator-facing mode; the live path is rejected at the BFF, control plane,
`chvctl`, and WebUI (#656/#683) because concurrent-write migration is not
claimed. The #582 follow-ups landed: residue clearing (#583), the T=0 skew
echo guard (#584), the WebUI toggle with an honest full-transfer-downtime
warning (#585), and the convergence guard (#590).

### LVM is VM-integrated

LVM is no longer a stord-layer-only capability (#379, closed). Per-volume
`storage_class` is carried end-to-end (#510/#511/#512): LVM boot volumes are
created on open with an explicit size, inventory reports the real class, an
unsupported class is rejected at accept time, and disks use dm-path locators.
The m4.5 Leg G end-to-end boot-volume run passed in the qualified lane.

### Network policy dispatch

Network firewall policy now dispatches end-to-end (#355, closed): a
`networks/update` carrying rules journals `UpdateNetworkPolicy` and fans the
stored ruleset out to every node with a live attached VM (#565/#566/#567).
The dead UI firewall editor was removed (#451), and legacy empty-ruleset call
sites are guarded (#360, #452). Empty or never-set rulesets become the DP4
baseline (DHCP/DNS/conntrack allowed, default-deny otherwise).

### Correctness and UX

- Journaled VM creates that hit a transient effector failure are re-driven by
  a bounded pass instead of terminating silently (#368, #484).
- The volume snapshot family is rejected at accept time on core-managed nodes
  (HTTP 400 before journaling) instead of being accepted and failing later
  (#378, #495).
- Owner stamping for imported/template volumes (#386, #481), clone/upsert
  concurrency fixes (#384), respawned-stord config fidelity (#385),
  independent migration halves (#401/#483), migration-rejection observability
  (#402/#479), and the delete-path kill-refusal fix (#351/#415) are on `main`.
- UI accessible names now match visible button text (#712).

### Fixes landed after the qualified candidate

These fixes are on the v0.4.0-rc.1 branch but are **not** part of `e82d49a1`.
They must be re-qualified before the RC claims them.

- The agent's Prometheus endpoint (`:9901`) now exports the process global
  registry, so the VM-operation and gRPC-server duration series the recording
  rules read are actually scrapeable there. The rule-backed duration
  histograms — including the BFF's `http_request_duration_seconds`, recorded
  in the control-plane process and exposed on its `:9103` listener — now
  render as bucketed histograms instead of summaries (#702).
- The first-enrollment bootstrap result is reported on the newly issued node
  identity, so a successful first enroll records its bootstrap result and no
  longer audits a spurious denial (#709).
- A post-restart delete recovers the stord session from the durable session
  table and closes detached sessions after detach, including a session left
  behind by a crash between detach and close (#711).
- The credential-encryption key source is explicit and logged; the
  `CHV_JWT_SECRET` fallback is deprecated, and new deployments must use the
  dedicated key (#336).

### Qualification harness and real-KVM evidence

The nightly real-KVM lane caught configuration drift the packaged path did not
(the split agent-auth secret and per-scenario stord metrics ports) and was
fixed in #710 (#659). The full lane is green on `e82d49a1`
([41938443045](https://github.com/o3kio/chv/actions/runs/41938443045)):
m4.3–m4.8 all `rc=0`, every per-scenario evidence directory present, 9
documented warnings, 0 failures. The host-state/orphan-harness hygiene,
failure observability, migration-auth minting, and stop/delete contract fixes
are harness-side only and do not change the candidate. See the
[nightly evidence note](../evidence/production-readiness/v0.3.0-rc1/04-real-host-qualification/nightly-kvm-2026-11-04.md).

## 3. Known limitations

Copied from the [support matrix](v0.4.0-rc.1-support-matrix.md); the
authoritative list is
[`DEPLOYMENT-ARCHITECTURE.md` §9](../DEPLOYMENT-ARCHITECTURE.md#9-known-boundaries-and-residual-risk).

- **Single host only.** Multi-host control-plane/agent dispatch is
  architecturally absent; ADR-029 is accepted but not implemented. The
  VXLAN/WireGuard fabric is design-only.
- **VMM/serial containment.** Cloud Hypervisor is pinned to v53.0. The silent
  serial-manager thread death and the adopted-VM stop wedge are contained,
  not cured; re-verify at every VMM upgrade (#345 root / #409).
- **Migration is stop-the-world only.** Pause-first is required; live
  concurrent-write migration is not claimed. The underlying stord primitive
  assumes a quiescent source. One multi-volume convergence-skew residual is
  disclosed (#582).
- **Backup/restore is hard-fenced.** All backup/restore routes return
  `501 NOT_IMPLEMENTED`; there is no DR claim or restore validation.
- **Storage.** Local file and LVM are qualified; Ceph RBD and iSCSI are coded
  but unqualified. K8s/CNI, Docker-forwarded, and multi-bridge coexistence are
  not claimed.
- **Upgrade.** Package upgrade is CI-verified; rolling node upgrade is absent
  (the old stack was deleted in #213), and downgrade is unsupported. The
  fresh-host install+upgrade demonstration (#666) is **not done**, and the
  quick-install leg (#556) is open.
- **Scale.** No concurrency, density, throughput, or requests-per-second
  claim. M4.8 numbers are single-host baselines.
- **Hardware minimums.** "4 cores / 8 GB RAM / 50 GB disk" is an unevidenced
  recommendation, not a qualified envelope.
- **Residual operations.** M2.5 delete retention (BFF/CP rows, VM dir, volume
  row, backing file persist); JWT/encryption key coupling (#336); and distinct
  `metrics_bind` values are required when running more than one stord per host.
  The detached-open session (#711) and first-enrollment bootstrap audit gap
  (#709) residuals apply to the qualified candidate `e82d49a1`; the fixes are
  on this branch and require re-qualification before the RC claims them.
- **UI evidence scope.** The UI was not re-qualified end-to-end in prompt-04;
  scenario evidence is chvctl/BFF/API-driven (with the network-policy path
  driven through the BFF in the 2026-11-04 lane).
- **Volvisor is design-only.** ADR-028 selects it as the future storage
  authority; runtime integration is pending. The qualified path remains
  `chv-stord`.

## 4. Upgrade notes

- Back up the control-plane SQLite database before upgrading; migrations are
  forward-only and **downgrade is unsupported**. The manual rollback procedure
  is in [`package-contract.md`](package-contract.md).
- Package conffiles are `config|noreplace`; services are **not** restarted
  automatically on upgrade. Restart the units explicitly and confirm the
  four services are healthy.
- Run more than one stord per host only with distinct `metrics_bind` values;
  the default `127.0.0.1:9101` is not multi-instance-safe.
- Re-save networks after upgrade if they carry pre-#365 NULL gateways or
  pre-#369 dialect rules; pre-#481 imported/template volumes remain
  ownerless/admin-only.
- Migration operators must pass `--pause-first` (`chvctl`) or use the WebUI's
  mandatory pause-first control; the live path is rejected by design.
- Install/upgrade on a fresh host is not yet demonstrated (#666). Treat the
  current install instructions as supported by the m4.2 container/install-sh
  legs and the package lifecycle CI, not by a fresh-host gate artifact.
